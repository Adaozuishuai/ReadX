# CBCT 论文每日精读助手 — Windows 版

本仓库**现在只包含 Windows 客户端**（Electron + TypeScript）。此前还有一版 macOS 原生应用（SwiftUI + PDFKit），已从仓库移除；本目录的纯逻辑由它逐条移植而来，本地数据格式与它完全一致。

## 与早期 macOS 版的关系

早期 macOS 版是 SwiftUI + PDFKit 原生应用（约 9600 行 Swift）。SwiftUI / PDFKit **在 Windows 上不存在**，所以 Windows 版不是"重新编译"，而是**新写一个客户端 + 移植可复用的纯逻辑**：

| 层 | 早期 macOS 版 | Windows 版 | 复用程度 |
|---|---|---|---|
| UI（约 7000 行） | SwiftUI 视图 | TypeScript + HTML/CSS | 重写 |
| PDF 渲染 | PDFKit | 系统关联阅读器打开 | 重写 |
| 纯逻辑（约 2600 行） | Swift | TypeScript | **逐条移植** |
| 本地数据 | `queue.json` / `papers/` / `library/` / `app/data/*.json` | **完全相同的文件与格式** | 共用 |

关键点：**数据格式与 macOS 版完全一致**。用 Windows 版打开同一个项目根目录，读到的就是同一份笔记、状态、全文缓存，不需要迁移脚本，也不需要账号或云同步。

## 怎么跑

需要 Node.js 18+（开发时用的是 Node 23）。

```bash
cd windows
npm install
npm start          # 构建并启动
npm test           # 移植保真度 + 模块回归（293 项）
npm run dist:win   # 打 Windows 安装包（NSIS + 免安装版）
```

工作区根目录的解析顺序（与 macOS 版同一机制）：

1. 环境变量 `CBCT_ROOT`
2. 从可执行文件所在目录向上最多 8 层，找含 `queue.json` 的目录
3. 当前工作目录

也可以从菜单「文件 → 切换工作区…」直接选包含 `queue.json` 的目录。

## 本版实现范围

**界面已复刻 macOS 版的 Fun 视觉与结构**（2026-10 对齐）：

- **主题配色** —— 复刻 macOS `Color` 扩展：纸白 `#FFFDF8`、主强调紫 `#6C5CE7`、青 `#336B78`、粉彩六色（yellow/pink/mint/blue/lavender/peach）、24px 圆角面板 + 1.5px 黑描边 + 淡阴影、背景装饰圆。排版尺度与 `Typography.swift` 同值。
- **导航壳** —— 顶部白色胶囊栏：笑脸 Logo「CBCT Daily」+ 今日/论文库/主题/想法 胶囊 Tab + 全局搜索 + 「⋯」溢出菜单（对比 / 知识地图 / 趋势 / 导入 PDF / 导出研究资产 / 设置）+ 研究画像按钮。
- **今日（仪表盘）** —— 三列 5/3/4 网格：**Adventure 卡**（1 快速浏览 / 2 深入精读 / 4 建立关联，带当前步高亮）、**连续阅读**（连击天数 + 本周格子）、**主题花园**（关注主题胶囊）、**知识图谱**（CBCT 中心节点的连线图）、每日摘要、为你推荐、预印本独立入口、按主题浏览分组。
- **论文库** —— 搜索框（标题/摘要/标签/笔记）、状态筛选（全部/收藏/未读/稍后读/精读中/已读/忽略/不相关）、**编辑器弹窗**（状态 / 收藏 / 推荐反馈 / 自定义标签 / 系统标签含命中依据与「未涉及」类别 / 个人笔记 / AI 纠错）、批量引用导出、**回收站**（恢复 / 彻底删除）。
- **研究画像** —— 六主题权重（关闭/关注/重点/核心）+ 任务/数据集/技术偏好/指标/硬件，保存后更新推荐。
- **主题 / 知识地图** —— 知识图谱 + 主题计数列表 + 趋势与缺口（时间窗+样本数+证据三要素）+ 想法↔论文关联。
- **精读室** —— 4 步结构（① 问题感 ② 读原文 ③ 挑毛病 ④ 留笔记）+ 子面板（论文动机 / 方法与公式 / 实验配置 / 结果分析）+ AI 助教（范围/模式切换、流式、Page N 跳转高亮）+ 精读笔记 + **Baseline 方法卡片**（领域常识、命中依据、与本文关系）+ 迁移到我的研究。

**第一版（核心工作台）**：

- **今日论文** —— arXiv / PubMed 抓取、单源故障降级、首见日期追踪、今日新增计数
- **自动导入全文** —— 论文卡片与精读室提供「下载并导入」：按论文的公开 `pdfUrl` 下载 PDF，用 pdfjs 抽取按页文本，写入 `library/` 与 `library/text/`；发现页还有「自动导入全部正式论文」批量入口。不绕过任何访问限制；扫描件抽不出文字会如实报告而非写空缓存
- **论文库** —— 搜索、状态切换、收藏、笔记自动保存（500ms 防抖）、系统标签
- **精读室** —— 原文（按页渲染）+ 精读笔记 + AI 助教（流式、范围切换、Page N 跳转高亮）
- **设置** —— API 地址 / 模型 / Key（Key 只写本地文件，不回显）
- **导入本地 PDF** —— 复制到 `library/`

**第二版（补齐可移植模块）**：

- **对比** —— 2–8 篇横向对比、**固定列**（提到最前，再点取消）、跨协议可比性警示、BibTeX / RIS / Markdown / CSV 导出
- **趋势 / Research Gap** —— 系统标签聚合、时间窗口 + 样本数 + 证据集合三要素、样本不足拒下判断、红线措辞自检
- **研究想法** —— 问题/观察/假设/方法/验证实验、五种状态、证据带来源类型、Markdown 导出
- **结果表校验** —— 表结构校验（含**列序位置校验**）、单位证据、解读与表/图绑定
- **系统标签** —— 八类派生、命中依据词、覆盖报告（哪类无证据如实显示）
- **复现准备** —— 从论文库进入；五组分析校验、分析指纹、按版本隔离的核对清单、仓库依赖提示（`repoChecks` 规则扫描）
- **结果分析** —— 校验入口（含**列序位置校验**）、两方法差值计算（分母 0 / NaN / 溢出都拒绝）
- **分层精读生成** —— TL;DR / 5min / Critical / 动机 / 方法公式 / 实验 / 结果 / 迁移，结构化产物保存前过证据校验（页码 + 逐字摘录）
- **Baseline 百科** —— PRD 点名的 FDK / SART / DuDoNet / C²RV / NeRP / Trans²-CBCT 加 IntraTomo3D，标来源类型、不确定留待核对、不做优劣推断
- **论文 ↔ 代码映射** —— 精读室「论文与代码」面板：扫描公开 GitHub 仓库（固定 commit、递归文件树、按类别往返选文件）、AI 生成概念↔代码映射、行范围与逐字摘录 + symbol 双来源校验、人工核对转「明确映射」。不执行仓库代码；token 只进请求头
- **LaTeX 公式排版** —— 离线解析引擎（分数 / 根号 / 上下标 / 大算子 / 黑体花体 / 重音），简单公式压成 Unicode 随正文换行；**遇到不认识的命令整式降级**为可展开源码，绝不半渲染
- **公式视觉转写与核对** —— 把 PDF 页光栅化后交多模态模型转成 LaTeX，再逐符号核对（运算符 / 上下标 / 希腊字母 / 分式结构 / 编号）
- **扫描版页面 OCR** —— 用 Windows 内置 OCR 把页面转成文本写入缓存（带 OCR 标记，提示人工核对）
- **架构图解析** —— 定位图题 → 光栅化 → 视觉模型提节点 / 连线 → **图内 OCR 逐标签核验**（编造的模块被剔除）→ 分层布局 SVG 渲染
- **页级向量检索（R-05）** —— 页级分块 + `/embeddings` 嵌入（端点不可用自动回退关键词）+ 本地向量索引；Chat 跨论文检索候选材料（标注来源，引用需写论文名 + 页码），只读本地索引不阻塞首响应

### 校验现在真正接入了界面

第一版做完时，`idea.ts` / `reproduction.ts` / `result.ts` 三个模块**只有测试引用，界面没有任何入口调用它们**——也就是「校验逻辑写好了，但用户实际点得到的路径不受保护」。这一轮把它们全部接到写入边界：

| 入口 | 校验 |
|---|---|
| 想法页「保存为想法」+ 证据表单 | `validateIdeaEvidence`（仅「论文原文」要求页码+逐字摘录） |
| `idea:importApplication` | `validateResearchApplication`（整条只有未知字段也拒绝） |
| 复现页「校验并保存」 | `validateReproductionAnalysis`（1–4 项/组、页码须真实存在） |
| `results:analyze` / `results:save` | `validateResults` + `validateBindings`（含列置换拒绝） |
| `results:difference` | 分母 0、NaN、溢出都返回 null 而非编造数字 |

## 刻意保留的硬约束

移植时**没有**放宽任何校验规则，因为这些是产品可信度的一部分，不是实现细节：

- AI 回答必须引用真实存在的页码，否则拒绝保存（`validateEvidence`）
- 实验抽取的每条事实必须有页码 + 该页逐字摘录；字段里的数字必须被摘录支持
- 材料超限时**如实披露**只取了 N/M 页，并禁止据此断言"论文没有该内容"
- `References` 对任何检索范围都强制排除（否则方法/实验范围会把参考文献整段吸进证据）
- 方法名中间的数字不算测量值（`IntraTomo3D` 的 `3` 不能被当作证据），但 `RTX3090`、`1.2GB` 这类型号数字保留
- 流式中断的回答**不保存**——半个回答比没有回答更危险
- 损坏的 JSON **不静默回退**默认值（否则下次保存会覆盖用户数据）
- 结果表的单元格不仅要比对数字集合，还要**按表头列顺序**逐字出现——否则列置换能整体通过校验
- 趋势样本数 < 5 时只报计数，**不下趋势判断**；缺口表述固定为「检索范围内未见」，不构成「首次」声明
- 可比性警示只在「两个以上不同的**已知**值」时触发；未知值不参与判断，避免误报
- 分析类建议每条都必须带原文依据；只有未知字段（没有一条带页码）会被拒绝

## 安全基线

- `contextIsolation: true`、`nodeIntegration: false`，渲染进程只能通过 preload 暴露的 IPC 白名单访问能力
- CSP 限制 `default-src 'none'`，`connect-src 'none'`（渲染进程不发网络请求，抓取与 AI 都在主进程）
- Markdown 渲染**不支持原始 HTML**，全部转义后再插入
- 外链只放行 `http/https`，防止被诱导打开本地可执行文件
- API Key 不回传渲染进程

## 已知差异与限制

诚实列出，避免误以为与 macOS 版功能完全对齐（该版已移除，此处仅作差异说明）：

1. **公式排版为 HTML/CSS 实现**：算法（LaTeX 解析、Unicode 扁平化、宽度估算、整式降级）逐条移植自 macOS `MathTypeset.swift`，但渲染层由 SwiftUI 视图改为 HTML/CSS 结构；视觉效果等价，不是像素级一致。
2. **PDF 用系统阅读器打开**：没有内置 PDF 阅读面板。Windows 版的 `Page N` 跳转是在左侧**全文文本面板**内滚动定位；页面光栅化（供 OCR/公式转写/图解析）在渲染进程用 pdfjs 完成。
3. **OCR 用 Windows 内置引擎**：扫描版页面用 `Windows.Media.Ocr`（无需下载模型）识别，写入带 OCR 标记的缓存；不是 macOS 的 Vision，识别质量随系统语言包而异，输出同样提示人工核对。
4. **图解析的裁剪由视觉模型给出**：macOS 用 Vision 在本地裁子图再逐块 OCR；本版让视觉模型给出归一化裁剪框，再用本地 OCR 逐块核验，核验不过即剔除——同一条「不猜」原则，实现路径不同。
5. **表格列宽均分**：按列数平分并夹在 96–320px，未按内容自适应。
6. **未设置应用图标**：打包时用 Electron 默认图标。

**已移植并接入界面**：主题配色、导航壳、Today 仪表盘、论文库（搜索/编辑器/回收站）、研究画像、主题/知识地图、对比、趋势、想法、复现准备、精读室 4 步 + 5 子面板、Baseline 百科、论文↔代码映射、分层精读生成、迁移建议、LaTeX 公式排版引擎、公式视觉转写与核对、扫描版页面 OCR、**架构图解析（FigureAnalysis）**、**页级向量检索（R-05：/embeddings + 关键词回退 + 本地索引）**。

## 移植过程中修掉的缺陷

都是「能跑但结果是错的」这一类，全部有回归测试 + 变异验证（故意改回错误实现，确认测试会失败）：

1. **节流写盘丢编辑**：`ThrottledWriter` 原实现在窗口结束时直接丢弃 pending，用户在去抖窗口内的最后一次输入永不落盘（重启后内容消失）。
2. **删除被回滚**：论文库状态每次改动都「重读磁盘 → 生成快照 → 节流写」。在打字窗口内「移入回收站」，窗口结束时落下的旧快照会让删除失效——论文约 600ms 后复活。改为所有写入共享一份内存权威状态。
3. **笔记段落静默丢失**：真实笔记标题带编号（`## 1. 问题设定`），而匹配用的是精确相等，导致除「一句话总结」外 5 个段落全部为空。
4. **标题首字被吃掉**：去编号正则把分隔符写成可选，`一句话总结` 变成 `句话总结`、`3D 重建` 变成 `D 重建`。
5. **页码锚点全部失效**：锚点查询 `h2`，但标题实际渲染成 `.md-h` 的 `div`；且标题里的 `Page N` 已被链接化，`id` 永远设不上，导致点证据链接无法跳转。
6. **证据链接破坏 HTML 结构**：在已生成的 HTML 字符串上跑 `Page N` 正则，会改写 `href` 属性内容，产出嵌套 `<a>` / 破损标签。改为「先转义、再以占位符插入链接」。
7. **有笔记的论文完全不可见**：只读 `queue.json`，导致唯一有全文缓存与笔记的 NAF（不在队列里）在 Windows 版看不到。现已合并 `papers/*.md`，与 macOS 版权重一致（笔记优先）。
8. **对比页字段读错来源**：把 `views` / `geometry` / `datasets` 当成库状态字段读，但这些字段实际在笔记 frontmatter 里。后果不只是显示「尚未抽取」——跨协议可比性警示**永远不会触发**（没有可比较的已知值，等于这条安全提示失效）。已改为「笔记 frontmatter → 已抽取实验字段 → 如实标未知」。
9. **`validateConfiguration` 缺失**：该函数由 macOS 侧在本移植期间新增（`ResearchModels.swift` 377→392 行），我最初读到的版本里没有。已补上并加回归测试。
10. **丢失了 Swift 解码期的结构保证**：Swift 的 `JSONDecoder` 解码非可选数组字段时，缺字段会以 `keyNotFound` 失败；`JSON.parse` 只把它变成 `undefined`。后果是模型少给一组时，校验崩溃成 `Cannot read properties of undefined (reading 'length')` / `a.statistics is not iterable` 这类 **TypeError**，而不是可读的校验消息。三个 decoder（results / idea / reproduction）都补回了结构检查。这是"移植时只搬了函数体、没搬类型系统提供的保证"的典型案例。
11. **三个模块写了但没接入界面**（678 行）：`idea.ts` / `reproduction.ts` / `result.ts` 只被测试引用，界面无入口，导致"校验只在测试里活着"。已全部接到写入边界，并补上想法页证据表单与复现页。

### 代码审查修复（独立一轮，2026-10）

对当前 Windows 端做了一轮缺陷审查，修掉 4 个「静默出错 / 丢数据」的缺陷，每个都先写探针复现、修复后加回归（`src/tests/fixes.test.ts`），并对其中一个做了变异验证：

1. **带版本号的 arXiv 论文匹配不到笔记**：`noteForQueue` 用未归一化的 arxiv 字符串比较，而 arXiv 官方 feed 返回 `2209.14540v2`、笔记 frontmatter 写 `2209.14540`，导致这类论文在库里丢掉「有全文缓存 / 已精读」标记（NAF 即此形态）。改为两侧都过 `arxivKey` 归一化。
2. **空 scope 导致「无原文作答」**：scope 为 `Appendix`/`Figure` 或无法识别的值时，材料为空但 `ai:prepare` 仍返回 `ok:true`，模型会在没有原文的情况下凭记忆作答，直接违反「没有可用原文时停止事实分析」。改为选不出内容即拒绝（抽成纯函数 `preparePaperMaterial` 以便测试）。
3. **保存覆盖损坏文件**：`reading:save` / `results:save` 在阅读记录损坏时用 `{}` 静默覆盖，而 `reading:get` 却报错——自相矛盾且违反「损坏不静默回退」。改为与 `reproduction` 一致，损坏即拒绝保存。
4. **library.json 损坏被静默清空**：`libState()` 损坏时当成空对象，下一次任何写入（改状态、记笔记、移入回收站）都会把整库状态覆盖成空。抽出 `core/libraryState.ts`（`LibraryStore`），损坏时记录原因并让写入返回错误，读路径展示为空；界面在自动保存失败时提示用户。

## 刻意保真保留的弱点

以下行为继承自早期 macOS 原版，移植**刻意不做「顺手修好」**，以保证与原版判定一致：

- `violatesRedline("no claim of being first to do this")` → `true`。否定标记 `no claim of` 距离禁用语 `first to` 超过 12 字符窗口，未被识别为否定语境。
- `violatesRedline("not the first「首次」")` → `true`。`negationMarkers` 里存的是整串字面量 `"not the first"`，中间插入引号后无法匹配。
- `violatesRedline("不是这回事，但这是首次提出")` → `false`。`不是` 落在 `首次` 前 12 字符内，整句被当作否定语境放行——尽管 `不是` 否定的是别的事。

这些是**放宽判定**或**误判**方向上的弱点（前者可能漏拦「首次」声明，后者可能误放）。它们继承自早期 macOS 原版并保真保留，当前只在这一版维护；如需修正，请重跑 `npm test` 确认红线相关断言。
